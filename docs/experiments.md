# 工作负载与批量实验设计

关联 [#11](https://github.com/xuzheluo0516-bit/capstone-cache-simulator/issues/11) 和 [#12](https://github.com/xuzheluo0516-bit/capstone-cache-simulator/issues/12)。生成数据置于 `data/generated/`，批量结果置于 `data/experiments/`；教授给出的 `data/reference/` 文件保持原样。

## 资源集与容量

参考 `resources.csv` 有 21 条资源。参考输出 A–E 只是其中五个资源，总计 169 KiB；仅请求它们时，500 KB 以上容量不会产生淘汰。参考库的两个视频是 44,462,080 B 和 59,637,760 B，在 10 MB 缓存下均不能进入，不能用它们单独验证“大资源挤出小资源”。

生成器因此使用独立的 `experiment.example.invalid` URL 与相应 8 列资源元数据。十二个可缓存资源的大小分别为 8、12、16、20、24、32、40、48、64、96、128、384 KiB，总计 **872 KiB = 892,928 B**。另有 44 MiB 视频，用于验证超容量请求绕过缓存，不作为可缓存竞争资源。每个输入文件均由现有 `load_inputs` 校验请求键唯一匹配。

默认容量以精确字节记录，分别为 32 KiB (32,768 B)、128 KiB (131,072 B)、256 KiB (262,144 B)、512 KiB (524,288 B)、1024 KiB (1,048,576 B)。前四档不能装下全部可缓存资源；最后一档可以装下 872 KiB，但视频仍绕过。混合负载的前缀先请求 11 个小资源，再请求 384 KiB 资源；在 512 KiB FIFO 缓存中，该请求可进入且实际淘汰小资源。参考测试的 100 KiB = 102,400 B 是独立的硬要求，不与本实验默认档位混淆。

## 三类负载

- `repeated`：单客户端，以 85% 概率访问前四个热点资源，其余访问十二个资源中的任意一个。
- `sequential`：单客户端，按固定顺序遍历十二个不同资源，完成一轮后再循环；一次遍历内部无重复。
- `mixed`：`browser` 反复访问小资源，`media` 访问 128/384 KiB 资源并偶尔访问超容量视频，`random` 访问十二个资源中的随机对象。固定前缀保证 512 KiB 条件有可观察的缓存竞争。

每类默认生成 72、360、1440 条请求（`small`、`medium`、`large`）。时间戳从固定 UTC 起点逐秒递增，方法为 GET，CSV 六列与真实请求输入一致。每个条件的随机流由总种子、类型和规模确定；相同配置与种子产生逐字节相同的资源与请求 CSV。`*_metadata.json` 记录生成命令、种子、请求数、客户端数、资源大小及活跃资源总大小。

## 跑批与审计

### 实验变量清单

- 自变量：负载类型（重复、顺序、混合）、规模（72/360/1440 条）、缓存容量（精确字节数）、替换策略（FIFO/LRU/LFU/CUSTOM）。
- 控制条件：同一条件下复用完全相同的资源与请求 CSV、种子、5 ms 命中延迟、空缓存初始状态、全请求计入统计且无预热；资源大小和源站延迟由输入 CSV 固定。
- 结果：请求命中率、字节命中率、平均响应时间、源站流量、逐客户端命中率与平均响应时间，以及逐请求事件。保存资源/请求哈希与代码标识，以便复核图表来源。


一条命令先生成全部输入，随后按负载、容量、策略跑批。**同一负载和容量的所有策略读取同一对 CSV**，每轮新建策略、引擎和指标累加器，从空缓存开始，全部请求都纳入统计，不做预热。命中延迟默认 5 ms。默认比较 FIFO、LRU、LFU、CUSTOM；自定义策略尚未进入当前基线时，默认运行会明确失败。可用 `--policies FIFO LRU LFU` 验证框架，但不能把三策略试跑称为正式四策略结果。

输出包括每轮十列原始 `events/*.csv`、总体 `summary.csv`、逐客户端 `clients.csv` 和 `manifest.json`。清单写明计划/完成次数、配置、精确容量、种子、输入文件与 SHA-256、代码 Git SHA（若可用）及源代码 SHA-256、Python/包版本、策略参数与每轮状态。默认策略参数为空对象；若自定义策略有构造参数，可用 `--policy-parameters-json params.json` 传入如 `{"CUSTOM": {"weight": 0.5}}`，清单会记录实际参数。失败记录错误并以非零退出码停止，不静默缺失结果。指标不变量检查包括请求、客户端和字节守恒；引擎和指标模块检查容量上限。每次运行覆盖现有 #8 指标，结果可用输入哈希和事件文件追溯。

正式解释策略优劣前仍需 #9 的三策略参考验证和 #10 的自定义策略实现与验证。这些依赖不阻止生成器与跑批结构先行评审。
