# Experiment method for the technical report

This section is ready for the 3–4 page team report. It describes the accepted experimental design and leaves numerical interpretation to the results section. It can be shortened during editing without changing the stated conditions.

We compared FIFO, LRU, LFU, GDSF, and our custom RW-CSF policy (`CUSTOM`) in a shared cache simulator. The three generated request traces represent repeated browsing of a small hot set, mostly first-time sequential access, and mixed clients with different browsing patterns. Sequential requests draw from a pool of at least 60 resources and repeat a prior resource on 12.5% of requests. Mixed traffic includes both a 384 KiB object that can enter a 512 KiB cache and displace smaller objects, and a 44 MiB video that is too large to be cached; after its fixed prefix occurrence, the video recurs about once per 100 requests. The older 12-object loop is available for a separate worst-case analysis but is excluded from the formal three-workload comparison.

Formal traces contain 1,440 requests per workload and use five independent seeds, `20261111`–`20261115`. Each seed is evaluated at 32, 128, 256, 512, and 1,024 KiB, with capacities stored in exact bytes. Every policy receives the identical resource and request files within each workload/seed condition. Each run starts with an empty cache, counts every request, uses a 5 ms cache-hit latency, and has no warm-up period. The main grid therefore contains 5 seeds × 3 workloads × 5 capacities × 5 policies = 375 runs.

RW-CSF's half-life was selected before formal evaluation. Candidate values 5, 20, 100, and 500 were evaluated only on tuning seed `31415` using the pre-registered response-time rule; the selected value was `H = 20`. The five formal seeds were not used to choose the parameter. We report request hit rate, byte hit rate, average response time in milliseconds, origin traffic in bytes, and per-client statistics. A hit contributes its resource size to hit bytes and 5 ms to response time; a miss contributes the full resource size to origin traffic and uses the resource's origin latency. Oversized resources remain misses and are included in all denominators.

For each workload/capacity/policy cell, metrics are computed per seed, then summarized as the mean and sample standard deviation over five seeds. This avoids pooling repeated requests across seeds. Fairness is evaluated separately through per-client hit rates and response times, including a Jain index computed from client hit rates. The committed `data/results/` tables, manifests, and six figures are the report's traceable results; `docs/results-audit.md` records the independent completeness and provenance check. The event-level and generated-input files can be regenerated with `d_experiments/run_all.py` but are not all included in the committed archive.
